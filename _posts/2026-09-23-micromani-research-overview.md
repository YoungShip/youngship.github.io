MicroMani 的记录最初按时间推进：先解决采集稳定性，再整理数据和训练，随后进入工作原点、机械寻零、质量报告和控制安全。问题逐渐互相交叉后，只按“科研记录（一）（二）（三）……”继续往后编号，已经不足以回答更重要的问题：**某个具体问题现在查到哪里、证据是什么、是否真的验收通过。**

因此这篇作为长期入口：原有时间线文章继续保留，重要问题再按主题归类，并统一标记状态。以后新增实验可以继续写阶段记录，但结论必须能回到这里找到自己的主线、证据和验收边界。

## 一、状态标签

| 标签 | 含义 |
| --- | --- |
| 已定位 | 已有代码、日志或实验把问题缩小到明确机制，但不代表修改已验收 |
| 已修改待验收 | 已有针对性代码修改，尚未完成对应实机或完整回归 |
| 离线验收通过 | 自动化测试、离线数据或仿真验证通过，仍不能替代真实设备验证 |
| 真机验收通过 | 在明确设备、流程和边界下完成重复实机验证 |
| 临时方案 | 当前可绕过问题，但不能作为最终设计 |
| 未解决 | 已观察到问题，但根因或可靠修复仍未闭环 |
| 已否定假设 | 经过对照后，不再把某个早期猜测当作主要解释 |

“代码已经改了”“测试绿了”“现场这一次正常”都不直接等价于“问题已解决”。

## 三、五条研究主线

### A. 机械系统与运动控制

| 问题 | 当前状态 | 当前结论 |
| --- | --- | --- |
| 工作原点作为统一任务起点 | 已定位 / 已投入采集 | 工作原点承担任务复位语义，应与机械寻零、机械参考点分开 |
| 2026-09-24 右臂拟重设工作原点 | 待执行 / 待验收 | 已保存设置前控制卡脉冲与旧工作原点读数；设置后必须核对新脉冲及相对零状态 |
| Roll 等旋转轴回零绕圈 | 已定位部分机制 | 日常返回已知位置不应再次机械寻零；异常大旋转需要独立拒绝条件 |
| 寻零过程中错误保存中间 pulse | 已修改待验收 | 旧版把 `dmc_home_move()` 启动成功与寻零完成混淆；修复需要等待 home result、done 和新鲜静止反馈 |
| X/Z 等轴找不到 HOME | 未解决 | 已知会持续运动至端部/超时；仍需核对 HOME 输入、方向、限位逻辑和物理轴映射 |
| 限位端作为机械参考 | 临时/受约束方案 | 只有明确停止原因、输入位、稳定时间和安全条件满足时才允许记录，并必须保留来源 |

### B. 遥操作与控制链路

| 问题 | 当前状态 | 当前结论 |
| --- | --- | --- |
| Omega.7 操作者侧与硬件侧映射 | 已定位 | participation、数据契约和日志必须使用一致的侧别语义 |
| DDS 命令应答并发 | 离线核对通过 | reply 按 `request_id` 关联，并有互斥与条件变量；未发现 lease 请求抢走普通命令 reply 的证据 |
| backend 维护 HAL lease | 已实现但待安全补强 | 能降低 UI 调度抖动导致的误断控，但不能只用 TCP/WebSocket“仍连接”代表操作者界面仍活着 |
| browser liveness | 未完整闭环 | 需要独立 heartbeat；浏览器失活后 backend 应停止替它续 HAL lease |

### C. 数据采集与系统稳定性

| 三路相机 30 FPS 与设备绑定 | 真机阶段验证通过 | 已有 120 秒和后续录制记录支持三路稳定采集，但不能外推到所有长期负载 |

## 五、近期优先级

当前软件开发已经进入提交后的现场数据验收阶段，最重要的不再是同时追多个旧问题，而是把新的实验基准固定下来，并用最小样本先证明采集链路仍然一致：

1. **先核验 2026-09-24 右臂工作原点重设。** 读取新原点脉冲和相对位置，确认后再固定新 W、三路相机、非活动臂、A/B 和 26 mm 夹爪起点。
2. **先采 3～5 条 probe。** 完整审计 origin、首帧 W+26、三路视频、lateFrames、cameraDrops、gripper/HAL/Omega stale、时间戳和 action jump。
3. **probe 通过后再扩大示教量。** 第一版目标约 30～40 条，训练/验证在训练前按完整 episode 固定划分；V1 仍保持固定 A/B。
4. **用新数据重训 relative ACT。** state/action normalization 只从新训练集计算，不沿用 standard10 统计，不在同一轮同时改变网络结构和数据定义。
5. **重复离线部署审计和 Live Dry-Run。** 继续验证 chunk 策略、adapter、安全门和完整环频率。
6. **再进入低速空载和单次 A→B 真机验收。** 真实运动仍需单独的安全计划与明确授权。
7. **V1 跑通后再做模型与泛化对照。** 包括 JEPA 路线、公平吞吐比较，以及 V2 的 A 点小范围扰动。

旧的机械寻零、控制租约、participation 和质量报告问题继续保留在问题索引中，但不因为它们曾经存在，就把已经完成的软件开发阶段重新写成当前唯一阻塞项。新 probe 会提供更直接的现场证据，判断这些链路在当前版本和当前硬件布置下是否真正稳定。

## 六、以后怎样写科研记录

后续文章继续保留时间线，但至少回答四件事：

- 这次解决的是哪条主线；
- 证据来自现场观察、日志、代码、离线测试还是真机重复实验；
- 状态从什么变成了什么；
- 哪些结论仍然不能说。

历史文章不为了后见之明而改写当时的判断。后续若推翻早期假设，应在新记录中明确写“已否定假设”，并链接回原记录。

## 七、当前整理结论

现在的 MicroMani 记录已经不只是训练日志，而是从机械运动、遥操作安全、数据采集、数据契约一路延伸到模仿学习的完整工程研究链。

从这篇开始，**时间线继续保留，但问题状态成为第一索引。** 无论后面继续调 X/Z 寻零、查控制租约、补示教数据还是重新训练模型，都先确认依赖是否已经验收、哪些结论仍只是候选解释、下一次实验究竟要关闭哪个不确定性。

本总览只整理已有记录和当前已知状态，不替代各篇文章中的原始证据，也不把本地未提交代码或未完成实机验证写成最终结果。
