> 这是一篇建站时附带的示例文章，用来展示排版和写作方式，不是站主的个人经历。熟悉之后，可以修改或删除。

## 先写下来，不必一步到位

一条想法、一段学习笔记，或者一次问题的解决过程，都可以成为新的记录。文章使用 Markdown 编写，只需要关注文字本身。

## 常用的写法

用 `##` 写小标题，用空行分段。文字可以 **加粗**，也可以加上 [GitHub Markdown 写作指南](https://docs.github.com/zh/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax) 这样的链接。

- 笔记：记下学到的东西。
- 踩坑：留下现象、原因和解决方法。
- 随想：不用等想法完全成熟。
- 生活记录：保存值得回看的片段。

写技术笔记时，可以放入代码：

```js
const note = "今天又学到一点。";
console.log(note);
```

## 发布一篇新文章

1. 打开本站 GitHub 仓库的 `_posts` 文件夹。
2. 新建文件，名字使用 `年-月-日-英文短标题.md`，例如 `2026-09-21-my-first-note.md`。
3. 按下面的格式填写标题、摘要和分类，再写正文。
4. 点击 **Commit changes** 保存。等待 GitHub Pages 自动更新后，就能在首页和「记录」中看到文章。

```yaml
---
title: "我的第一篇笔记"
description: "用一句话概括这篇记录。"
category: 笔记
tags: [学习]
---

这里开始写正文。
```

分类可以填写「笔记」「踩坑」「随想」或「生活记录」。文件名中的日期不要晚于当天，否则文章会等到该日期后的一次重新构建才出现。

## 公开之前，检查一下

这个小站和它的源码仓库都是公开的。不要写入密码、密钥、私人联系方式或不准备公开的内容；草稿也建议先保存在自己的电脑里。

想修改个人简介时，编辑仓库里的 `about.html`；想修改首页介绍时，编辑 `index.html`。网站的字体、间距和颜色会统一应用，不需要每篇文章单独设置。
