## 结论与复盘范围

本轮讨论与接口搭建始于 **9 月 27 日**，主要抓取、视角探索和力试验发生于 9 月 28 日，9 月 29 日完成归位与收尾。目标从远程替代人工采集收敛为“先抓起台面小环一次”。**没有成功抓起零件，没有形成成功抓放示教数据，也没有完成真实接触触发停机或恒力控制验收。**

本次复盘按顺序阅读了分享会话中全部可见的用户消息、助手答复和进度说明，并结合本地实验记录核对。分享页隐藏了插件调用、工具输出及部分附件，不能称为完整原始遥测审计；数字优先以本地记录为准，只有对话陈述的内容单独注明。公开演示中曾被提及的成功率没有在本轮重新核验，也不作为本实验基线。

最终按用户要求撤回实验代码：共享三文件恢复至实验前的 Git HEAD，新增入口、测试、脚本及独立产物从工作目录移除，源码和原始日志仅留归档。MicroMani 工作区及暂存区恢复干净，没有推送实验代码。

## 控制架构与目标如何变化

最初启动了已有 MicroMani 软件，尝试通过 backend / HAL 读取状态和预演。随后按用户要求改为复用底层接口：相机仍由 backend 提供快照，位置与单轴指令走 LTDMC，夹爪走 Jodell。旧 HAL 被停止以释放控制卡。早期“右臂”被误解过一次，错误侧只做了 `sent=false` 的 dry-run，纠正为操作者右臂后才进入运动。

| 对象 | 本轮含义 | 不能混用的概念 |
| --- | --- | --- |
| 操作者右臂 | 硬件 left / card1，抓取臂 | 不按硬件 left/right 名称猜操作者侧 |
| 操作者左臂 | 硬件 right / card0，观察臂 | 左腕相机随该臂调整，不是独立 PTZ |
| XYZ | 用户确认机械 Z 为上下；本轮按 X 左右、Y 前后理解 | 斜视画面的左右、上下投影不等于机械方向 |
| 控制卡位置 | 命令位置脉冲及其单位换算 | 不是外部编码器、指尖实测位置或净空 |
| 夹爪“毫米” | 软件根据行程配置映射的开口反馈 | 未标定为实际指尖间距，也不是夹紧力 |

用户明确要求 GPT 边看图边调整，不接 ACT。可选 HTTP 服务曾通过本机 Codex CLI 指定 `gpt-6-astra` 生成结构化动作提议；主要抓取阶段由当前会话代理直接看图、读状态并调用执行工具。服务的 HTTP 执行入口一直关闭，但会话代理仍能调用独立运动桥，因此“HTTP 禁用”不等于机器人没有其他执行入口。

底层程序是确定性执行代码，伺服循环内没有内置语言模型。回 W 的批量小步由确定性脚本执行，不能描述成每个小步都由 GPT 重新看图决策，也不能把整个会话的模型身份等同于独立 CLI 配置。用户从逐步批准改为整任务授权后，任务未完成不能再归因于没有批准。

## 实验过程与阶段结果

| 阶段 | 实际执行与观察 | 结论 |
| --- | --- | --- |
| 小步试探 | X +3 μm 已执行，但图像不能可靠辨认；X +1 mm 产生约 4–5 px 变化；两次 −50 μm 约 0.22 / 0.24 px，之后 −1 mm 约左移 4.4 px | 得到局部方向和尺度经验，不是全空间手眼标定 |
| 首轮抓取 | 记录至 step72，逐步对齐、调整约 21° 腕部倾角、闭爪并抬升，五次抬升均未带起零件 | 仅凭零件位于两指投影之间会误判夹持，退高后暂停 |
| 首次观察角度调整 | 观察臂 Roll 约 −24.87°、Pitch −5°；平台进入画面，目标仍被机体遮挡，随后恢复原计数与视角 | “看见平台”不等于“看见接触间隙” |
| XYZ 方向试动 | 各负向 1 mm；近物图像 X−约向右 4.7 px，Y−向下 4.3 px，Z−向上 2.4 px；回程 X/Y 有限位残差 | 用台面孔位区分背景移动与臂部移动，保留真实残差 |
| 仅 X/Z 调整 | 保持 Y、角度与抓取臂不变，探索至 step94；相对该轮起点净 X −0.1 mm、Z −76.0132 mm，Z 遇限位后退回 1 mm | 银环完整可见，两指尖仍未可靠分开；位移来自命令计数 |
| Roll 归零与角度再探索 | Roll +0.1242° 恢复为 0°；保存回退点后做 14 步探索，较佳观察位为相对 W 的 Roll +7.9992°、Pitch +4° | 两指与小环可分辨，但没有得到标定后的接触高度 |
| 续抓取 | 29 步、四次抬升未成功；最后一次闭爪可能推移、倾斜零件或改变遮挡，之后张开并退高 | 不能说目标始终未动；未分离高度、前后几何或夹持方式的影响 |
| 力监测与取消 | 双侧静态采样、软件保护和自由空间取消测试完成 | 证明读取及软件停止部分链路，未证明真实接触停止 |
| 力响应往返 | Z 两步下降共 0.2 mm，步后力矩预警暂停；低速原路回退后信号大部分恢复 | 位置相关变化与接触尚未分离 |
| 后续下压请求 | 右臂请求下降 2 mm，实际只走 0.2 mm，当次未回撤；左臂 Z 到下限位；右臂随后下降 1 mm 请求未执行 | 右臂暂停来自软件预警，不是右臂行程限位 |
| 归位与结束 | 两臂逐轴返回 W，保留左臂限位残差，停止 GPT 服务，随后撤回代码 | 未改工作原点，未机械寻零，未继续下压 |

两段抓取是在探索过程中改变姿态、位置和策略的重复尝试，不能把五次与四次抬升简单作为九个独立同条件 episode 来计算泛化成功率。较佳观察位也只是候选，结束时角度已恢复 W，不能把它当作当前仍生效的位置。

## 哪些判断需要纠正

**单腕相机与倾斜观察不是本次失败的已证实根因。** 会话中曾把“本次无法判断高度”表述得接近“必须标定／单相机抓不了”，后来已纠正。本轮只说明所用观察与决策方法没有可靠识别接触几何；既没有证明必须垂直下抓，也没有证明调成垂直就能成功。历史成功示教可作姿态参考，不能直接重放旧坐标或下降距离。

**停止条件也有设计问题。** 在下降 0.2 mm 就出现可逆载荷变化后，未完成空载位置响应建模，重复使用同一预警仍把接近挡在相似位置。用户观察指尖仍悬空；只读核查确认右臂 Z 两端限位均未触发。这个结果应记录为接触判据尚未具备区分能力，不能算力控成功，也不应将问题全部归咎于模型能力。

**初步视觉判断必须允许被后续证据推翻。** 首次抬升时零件看似仍在指尖之间，随后与台面背景对照才确认夹空。续抓取的四次抬升也使用了腕图台面参照及固定左腕视图。图像重叠、夹爪到位、计数到位都不能单独证明零件离台。

## 力监测：测到了什么，没有测到什么

原 HAL 的 `waiting_sensors / force_configuration_pending` 来自 MicroMani 的软件启动流程；当时不是传感器硬件碰撞报警。它与实验桥的力阈值、步后监督预警、控制卡限位是不同层次。采用独立接口不代表原 HAL 所有保护都没有必要。

| 证据 | 结果 | 适用范围 |
| --- | --- | --- |
| 双侧静态读取 | 约 10 秒、约 1 kHz，所检样本无 CRC / 非有限值错误 | 主机批量接收不是逐帧真实采样时间 |
| 噪声 | 后续原始力通道静态标准差约 27–32 mN；早期回复另报 100 ms 均值约 3–4 mN | 两者统计口径不同，且单位仍按软件约定，不能推出零件允许载荷 |
| 自由空间取消 | 计划上移 50 μm，取消后实际命令计数换算约 +9.2 μm；恢复原计数 | 人为取消，没有触发真实接触 |
| 停止耗时 | 停止 API 约 1.0642 ms；停止请求至新鲜停止反馈约 3.7032 ms；取消锁存至反馈约 4.7006 ms | 不是接触到物理停止延迟，不是过冲距离 |
| 固定参考探测 | 下降 0.2 mm 后末尾 200 ms 平均 Mx 变化约 −0.000981，超过监督预警 0.0008 | 原生接触阈值 0.0016 未触发；只是未发送下一步 |
| 专项测试 | 最终力保护核心 29/29、串口保护 11/11 通过 | 早期 34 项与最终 40 项属于不同代码阶段；不是生产 HAL 全量回归 |

固定参考避免逐步重新去皮掩盖累计载荷，但没有空载位置/姿态补偿；变化可能来自接触，也可能来自机构或线缆，本轮没有完成归因。观察臂后来位移后，旧双侧参考和十二轴位置前提也不能照搬。原生桥没有完成恒力、导纳或经验证的自动减载退出；固定参考甚至可能在带载时拒绝恢复方向。

本轮没有标定腕部六维读数与两指夹紧力的关系，不能用腕力低来证明没有夹住，也不能用传感器量程代替小环的允许载荷。物体材质、尺寸及真实承力边界未确认。

## 速度与采数据的缺口

会话当时报告单次规划约 **11–15 秒，较慢一次约 18 秒**，包含读取、拍照、CLI 调用与返回 JSON；完整观察—决策—移动—再观察约 15–25 秒只是当时估计，不含等待授权。本次没有从被隐藏的工具结果重建完整计时分布，不能将这些数字当作稳定 benchmark 或模型纯推理耗时。

普通位置桥平移为 300 μm/s；力探测为 50 μm/s，往返回撤为 25 μm/s。回 W 共 119 次有界动作。微步、拍照、远程往返、反复验证及修改服务共同增加耗时。没有 Astra / 5.6 Luna 同条件速度和成功率对照，不能据此宣称换模型即可解决效率或可靠性。

采数据还有两个独立问题：

- 现有录制器的 action 按 observation、teleop 增量和夹爪目标生成；本轮未将独立 GPT 指令接成已验收的动作来源。能控制机器人不等于按下录制就能得到正确监督标签。
- 检查时 `storage.recordForce=false`；抽查两份历史 parquet（428 帧、371 帧）的双侧力列均为零。结论只覆盖这两份样本；新桥另存的力 CSV 不会自动成为现有数据集的同步力观测。

本轮离散图片、JSON 和力 CSV 应保留为失败分析材料，不能直接声称是同步 LeRobot 成功示教。批量采集还需任务复位、动作与反馈时间对齐、来源标记及成败验收，这些都未完成。

## 代码撤回与设备收尾

本轮曾新增位置桥、力保护桥、测试、构建脚本、GPT 服务与 schema，并修改 CMake 和共享 HKVL 驱动。旧位置桥没有新增力保护；回 W 走的是旧位置桥，不能声称全部运动均受统一力保护。没有把新实验桥部署为正式 HAL。

03:17 停止 GPT HTTP 服务，确认 18106 端口关闭，无实验运动桥、力桥、夹爪 worker 或 HAL 进程；保留既有相机 backend。03:31 按用户最终要求完成代码撤回：

- 回退 `hal/CMakeLists.txt`、`hal/include/HkvlForceDriver.h`、`hal/src/HkvlForceDriver.cpp` 到实验前 `xie/44ba381`。
- 移除活动目录中的新增源码、测试、脚本、schema、服务说明、独立可执行文件及缓存；先完成 ZIP 归档并逐文件验证 SHA-256。
- MicroMani 工作区及暂存区均干净。暂存区原本为空，撤销的是未暂存改动和未跟踪新增文件；没有重置整个仓库，没有推送实验代码。
- 正式 HalServer / Jodell worker 二进制在撤回前后哈希一致。原始图像、轨迹、力数据及回原点证据保留，未重新运行硬件测试。

最后一次运动核验中，操作者右臂六轴计数与 W 完全一致；左臂角度一致，XYZ 相对 W 的换算残差分别为 **−7.6、−36.5、−10.2 μm**，受限位约束。共 9/12 轴计数精确一致，左 Y 残差超出当时驱动回原点容差，因此整体为 `partial_return_with_residual`。未改工作原点，未机械寻零，回 W 期间未操作夹爪。早先未执行的下压请求已被归位与结束任务取代。

## 后续研究与证据索引

本轮不继续运动，也不保留可直接启用的实验入口。若以后重启该研究，应先形成可检验的接触高度/夹持几何，再区分空载载荷与接触，统一执行保护和减载退出。完成一次可靠抬升后，再验证复位和数据标签，最后讨论批量采集。常规遥操作采集与 ACT 训练可独立推进，但应重新核对现场布置、W 残差及采集质量；本轮不能证明 ACT 必须或不必显式标定。
