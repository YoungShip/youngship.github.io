# MicroMani 科研记录本维护

由 `$blog-writing` 的科研模式调用，适用于科研同步、实验/排错收尾、阶段补记和会话归档；不用于一般随想。流程不授予发布、修改其他仓库或机械动作权限。

## 1. 恢复上下文

先读根目录 `AGENTS.md` 和本 skill，检查 Git 工作区、暂存区和远端。再读 `_posts/2026-09-23-micromani-research-overview.md`、`_posts/2026-09-29-micromani-research-status.md`、`_posts/2026-09-29-micromani-experiment-register.md`；它们分别负责阶段路由、当前问题/验收和数据/模型比较。沿编号和链接深读本次相关原文与实际证据。局部更新不必重审无关数据，矛盾、缺证据或全局任务必须扩大阅读。仅阅读公开资料时优先站点/GitHub，本地修改或未推送状态才用授权工具；不依赖固定电脑路径。

## 2. 按新增证据选择最小完整修改

先列事件日、整理日、问题、场景/数据、源码与运行版本、方法、实测结果、失败、决定和待办，与旧记录查重。已有问题的新进展：原专题追加日期补记，同编号台账更新；新阶段/独立故障：新文章进入总览时间线，复用或追加台账项；新数据/训练/评估：更新原文及实验索引；旧推断纠正：保留原时点，加证据和双向链接。没有新增事实、决定或待办时说明无需更新，不制造新文章。只改结构不记成新实验。总览保持短，当前状态集中台账，过程留原文，不在所有页面重复整张表。总览首段保持“**更新至 YYYY-MM-DD。**一句话现状：……”的写法并同步 `last_modified_at`，首页“此刻”卡片读取这一句。台账“状态”列只用“状态怎么读”里的状态词，网页才能给它们上色和筛选。

## 3. 状态与来源

A～E 问题编号稳定，新项接续各组最大编号，不能将旧号重新分配。D/M 检索标签不冒充真实 run ID。台账每项只占一行：状态词、约 60 字以内的现状与下一步、出处链接；证据日期、版本和关闭条件写在出处原文或其附录里，不堆进台账格子。总页更新不代表全部条目重验。区分源码已写、离线测试、候选合并、二进制部署、运行核对、现场一次正常和可重复任务通过；不移植其他工作区的测试。历史原点、限幅和快照不是当前状态或运动授权。本地路径只作真实证据标识，不捏造公开下载链接；分享页缺少工具结果/附件时说明范围，无法读取的依据标待核。

## 4. 数据、模型与指标

核对 setup/W、侧别/单位、清单和 episode 划分、训练统计/归一化、窗口与 mask、输入输出、模型/代码、随机种子/预算和评估集合；未知字段待核，不假定沿用默认。文件完整、任务成功、规范合格与本轮入训是四种判定；按最终清单取数，不扫描副本目录代替清单。first-step/full-chunk、训练拟合/best validation/独立 test 分开；不同集合与尺度不直接排名。跨批次重叠测试数不相加，历史测试不写成本次重跑。forward、完整 dry-run 和运动控制环分开，保护触发、空载运动与任务成功分别统计。数字冲突保留双方、引用出处并登记待核，无原始配置不猜改。

## 5. 正文写法

科研记录写研究，不写工作日志。结构见 `references/research-entry-template.md`。

- **先写发现，按问题组织。**开头给本阶段结论，正文按“要回答的问题”分节，每节先给结果再给分析；不按排查的时间顺序展开，没解决问题的尝试压成一小段放后面。
- **限定语集中写。**“不能据此”“不等于”这类限定集中到“能说 / 还不能说”，待核项集中到一节；正文只在结论确实容易被误读时点一句。
- **细节进附录。**提交号、测试数、精确时间戳、文件路径与哈希、拆分过程放进文末折叠附录；只有时间先后本身就是证据时（例如断连前后的毫秒时序），才在正文保留一张小表。
- **不写整理过程。**“本次阅读了……”“按会话顺序……”只放在页头的证据来源一句里。推测写明“推断，未验证”。
- **说人话。**短句，主语和动作写清楚，直接给具体数字、现象和原因；不用“值得注意的是”“综上所述”“进一步表明”“具有重要意义”这类套话，不堆形容词，不用一连串抽象名词代替一句具体描述。一句话能说清的，不拆成三条要点。
- **保留原有事实。**改写旧文只调整结构与表述，事实、数字、日期、链接和编号锚点一条不删。

## 6. 文稿与验证

旧文件名、发布日期、URL 与历史过程保留；事件日期和后补日期分开。文章顶部保留三个入口；网站会在页边自动生成目录，正文不再手写 `{:toc}` 目录。模板见 `references/research-entry-template.md`。公开前审查隐私、截图和附件；不上传整个会话、日志归档、数据集或草稿目录。执行 `python .agents/skills/blog-writing/scripts/check_notebook.py --root .` 和 `python -m unittest discover -s .agents/skills/blog-writing/scripts -p "test_check_notebook.py"`，使用已核对的 Python 3.8+。有生成站点时加 `--built-site <输出目录>` 检查真实 HTML 链接与锚点。源码结构检查不是完整 YAML/Jekyll 解析，更不代替实验真实性审查。

## 7. 发布与交接

没有本地 Jekyll 时不擅自安装全局环境或更换部署；发布获准后以实际提交的 Pages 构建与页面验收为准。发布前核对远端、diff 和暂存文件，保护其他 Agent 改动，不强推。不能直接推送 `main` 的环境（如云端会话）推送到会话分支，经 PR 合并后再验收。更新记录默认草稿；“更新并发布本次记录”授权本次相关原文与索引联动发布，无需逐文件反复确认，但不产生永久发布权。规则/skill/配置需对应授权。发布后核对提交 SHA 的 Pages 成功，再检查三个入口、受影响文章、目录/编号锚点及旧原点跳转；涉及导航需桌面和窄屏检查。失败如实报告并修复本次差异，不把 push 等同上线。交接报告更新文件/编号、证据范围、未解决项、下一步前提及草稿/发布位置；归档不删除原始资料。

可复用收尾请求：`按 YoungShip/youngship.github.io 的 AGENTS.md 和 $blog-writing 科研模式，把本会话新增进展同步到科研记录本；先查重，再更新相关原文、总览、台账和必要的实验索引，保留失败及待办并完成校验。此次更新并发布，报告提交、Pages 构建及页面结果。` 只写草稿时将末句改为“此次只保存草稿，不提交、不推送”。此提示不能替代新会话读取真实仓库状态。
